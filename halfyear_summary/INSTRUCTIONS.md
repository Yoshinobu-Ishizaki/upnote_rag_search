# 半期業務まとめ（人事評価入力用）

このフォルダは、人事評価入力のために半期分の業務内容を UpNote メモから
まとめるためのもの。Claude Code がこの手順に従って実行する。

評価月は毎年 **9月・3月**。対象期間は次の通り。

| 実行時の月 | 対象期間 |
|---|---|
| 4〜9月 | その年の **4月1日** 〜 実行日 |
| 10〜3月 | 直近の **10月1日** 〜 実行日 |

## 手順

1. 抽出スクリプトを実行し、対象期間分の UpNote メモを取得する。

   ```
   uv run python halfyear_summary/extract_period_notes.py
   ```

   - `data/upnote_text.csv`（前処理済みキャッシュ）ではなく、最新の `.upnx` バックアップを
     直接パースするため、直近の未反映メモも含まれる。
   - 標準エラー出力に対象期間・抽出ノート数・出力ファイル名（推奨）が表示される。
   - 抽出結果は `halfyear_summary/_period_notes.md` に書き出される（中間ファイル）。

2. `halfyear_summary/_period_notes.md` を読み、業務内容をトピック（テーマ）ごとに整理する。

   - 1件ずつ逐次要約するのではなく、内容が近いメモ（同一案件・同一カテゴリ・同一活動）を
     まとめてグルーピングし、トピック単位で「概要」「実施内容・成果」をまとめること。
   - カテゴリ（UpNote のノートブック階層）やタグは分類のヒントとして使うが、
     そのまま見出しにするのではなく、実際の業務内容から適切なトピック名を付けること。
   - 雑多な個人メモ・下書き・重複メモなど、人事評価に無関係な内容は除外してよい。
   - 文章は日本語の技術文書・業務報告として整った文体で書く。敬体・常体は統一する。
   - 文字種は NFKC 正規化に合致させる（英数記号は半角、ひらがな・カタカナ・漢字は全角）。

3. 出力ファイルを作成する。

   - ファイル名: `yyyy-mm_summary.md`（`yyyy-mm` は実行日時点の年月。ステップ1の標準エラー出力
     に表示される「要約ファイル名（推奨）」をそのまま使う）
   - 保存先: `halfyear_summary/` フォルダ直下
   - 構成の目安:

     ```markdown
     # {対象期間} 業務まとめ

     対象期間: yyyy-mm-dd 〜 yyyy-mm-dd

     ## {トピック名1}

     - 概要: ...
     - 実施内容・成果: ...

     ## {トピック名2}

     - 概要: ...
     - 実施内容・成果: ...

     ...
     ```

   - トピックの数・粒度は実際のメモの内容量に応じて調整してよい（多すぎる細分化は避ける）。

4. 出力後、中間ファイル `halfyear_summary/_period_notes.md` を削除してよいかユーザーに確認する。
   個人のメモ原文をそのまま含むためリポジトリには残さない方針だが、要約作成後にユーザーが
   生データを見ながら追加の質問をすることがあるため、指示なく自動削除しない。
   削除してよいと確認が取れてから削除する（`.gitignore` 済みなのでコミット漏れの心配はない）。

5. 作成した `yyyy-mm_summary.md` の内容を簡潔にユーザーへ報告し、
   コミットするかどうかユーザーに確認する（無断でコミットしない）。

## 備考

- `_period_notes.md` および `*_summary.md` は個人の業務メモを含むため、
  `.gitignore` に追加することを検討する（未追加の場合はユーザーに確認する）。
- 抽出対象は UpNote バックアップ（`config.ini` の `UPNOTE_BACKUP_PATH`）の最新 `.upnx` ファイル。
  バックアップが古い場合は、UpNote アプリで先にバックアップをエクスポートし直すよう
  ユーザーに案内する。
